# 개인 기록 백업·가져오기·복구

PR #11 개선안 기준이다. 병합·배포 승인 전에는 공개 사이트와 화면이 다를 수 있다.

개인 기록은 이 브라우저의 localStorage에만 있다. 로그인 계정 동기화, 개인 기록 자동 클라우드 백업은 제공하지 않는다. 홈페이지 소스/Git 백업에는 개인 기록이 들어 있지 않다. 비공개 모드 종료·사이트 데이터 삭제·기기 변경 전에 개인 기록 JSON을 별도로 보관한다.

## 내보내기

홈 화면의 `개인 기록 백업(JSON)`을 누른다. 피드 조회가 실패해도 백업 도구는 표시된다. 파일명은 KST 날짜·시각을 포함하며, 파일 안에는 서비스 식별·버전·UTC 생성 시각·항목별 건수가 있다. 파일 다운로드를 요청했다는 안내가 실제 디스크 저장 확인을 대신하지 않으므로 내려받은 파일을 직접 보관한다.

지원하는 기록은 saved(저장 ID), apps(상태·메모·체크리스트·날짜·공고 정보), prefs(맞춤 조건), spec(스펙), 가져온 원본 보관함이다. 최근 변경·가져오기 복구 사본도 보관한다. SDK 저장소는 허용목록에서 제외한다. 알려진 인증 필드가 있으면 제외한 건수와 원문에서 제외한 키를 파일에 표시한다. 따라서 그 경우 `raw_records`는 인증 필드를 제거한 사본이며, 모든 바이트가 동일하다고 설명하지 않는다.

백업에는 개인 메모가 포함될 수 있다. 파일은 본인이 안전하게 보관하고 공개 저장소나 채팅에 올리지 않는다. 이 JSON은 암호화 파일이 아니다.

## 가져오기

`백업 가져오기`에서 파일을 선택한다. 최대 16MB, 형식 `careerpick-backup`, 버전 1만 지원한다. 먼저 생성 시각·버전·항목별 건수·신규·중복·충돌·가져올 수 없는 항목 수와 영향을 확인한다. 형식·버전·내용이 잘못됐거나 부분 백업이면 기존 기록을 바꾸기 전에 중단한다.

확인하면 현재 기록 백업을 요청하고 검증한 기기 내 복구 사본을 만든 뒤 병합한다. 저장 목록은 합집합이며, 같은 공고 ID에서 내용이 충돌하면 기존 객체 전체를 보존하고 가져온 원본을 보관함에 남긴다. 수정 시각만으로 어느 쪽이 최신인지 단정하지 않는다. 다시 가져와도 공고·같은 원본 스냅샷은 중복되지 않는다.

출처 접두사가 있는 ID는 그대로 유지한다. 접두사 없는 과거 ID의 출처를 제목·기관명으로 추정해 다른 공고와 자동 연결하지 않는다. 현재 목록에 없는 ID·지원 메모도 삭제하지 않는다. 저장 해제가 지원 내역을 지우지 않는다.

## 충돌과 실패 복구

`충돌·복구 사본 확인`에서 가져온 원본과 최근 복구 사본을 텍스트로 확인할 수 있다. 백업 내용의 HTML은 실행하지 않는다.

가져오기 중 오류가 나면 변경 전 원문으로 복구한 뒤 다시 읽어 확인한다. 완료 여부를 확인할 수 없거나 중간 종료된 경우에는 다음 접속에서도 복구 필요 안내를 표시하고 추가 저장을 보류한다. 복구 사본 화면의 `최근 가져오기 전으로 복구`를 사용한다. 사본 이후 별도 변경이 있으면 자동 덮어쓰기를 중단하며 현재 자료와 원본 사본을 각각 보관해야 한다.

최근 복구 사본은 무제한 이력이 아니다. 브라우저 데이터 자체가 삭제됐거나 저장소·복구 사본 모두 읽을 수 없다면 내려받은 JSON이 필요하다. 손상 원문은 함부로 빈 기록으로 바꾸지 않으며 정상 부분을 표시하고 원본을 보관한다. 알 수 없는 내용을 추정해 복원했다고 보고하지 않는다.

## 구주소 이전

구주소 https://jobinfo-hub.github.io/ 와 새주소 https://kllollain-max.github.io/careerpick/ 는 서로 다른 origin이다. 새사이트가 구주소 localStorage를 직접 읽을 수 없다.

구주소를 사용하던 동일 기기·브라우저 프로필에서 JSON을 내보낸 뒤 새주소에서 가져온다. 구주소 접속 불가 시 과거 보관한 JSON이 필요하다. 실제 구주소 이용자의 개인 백업은 확보하지 않았다. **시험 데이터의 v1 호환성 검증과 실제 기록 이전 완료는 다르며, 실제 개인 기록 이전은 미확인이다.**
