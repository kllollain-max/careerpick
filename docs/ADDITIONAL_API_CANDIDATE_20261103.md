## 국가공무원 시험일정

기존 `civil-service-exams.html`은 이미 `data/civil-service/years.json`과 `2026.json`에 연결돼 있었다. 기존 자료는 **28개 시험단계 행·10개 시험**이며 조회 시각은 **2026-10-25 22:39:58 UTC = 2026-10-26 07:39:58 KST**다. 이번 검증 시각을 자료 조회 시각으로 바꾸지 않았다.

`mpm_exam.Client.collect()`는 기존 제한 안에서 전체 행을 수집·검증한 뒤 `records`와 기존 형식의 `verification`을 반환한다. `verify()`는 같은 수집 경로의 요약만 반환하므로 기존 사용처의 계약을 유지한다. 인증 검증 후 같은 자료를 다시 호출하는 이중 수집은 하지 않는다.

`validate_records(records, expected_count=...)`는 API 키·네트워크·현재 시각 없이 보존 자료의 스키마, 개수, 중복, 날짜를 검사한다. 원본 행을 바꾸지 않고 장소공고일 null만 복사본에서 빈 값으로 정규화한다.

| 기존 저장본 검사 | 결과 |
|---|---:|
| 시험단계 행 | 28 |
| 서로 다른 시험명 | 10 |
| 유효한 날짜 셀 | 107 |
| 장소공고일 null / 빈 날짜 셀 | 5 |
| 중복 행 | 0 |

화면에서 `2026-11-5~2026-11-6`을 정렬하지 못하던 문제를 수정했다. 날짜를 달력 기준으로 검증하며, 빈 일정은 “미정”, 잘못된 일정은 “공고 확인 필요”로 표시한다. “저장된 일정 기준”과 원서접수 마감·시험 종료의 차이도 표시한다. 조회 시각은 원래 순간을 한국시간으로 변환한다.

새 후보 파일은 검증한 날짜를 ISO 형식으로 정규화하고 변환 전 값은 별도 검토 JSON에 보존한다. 쉼표·슬래시로 나열한 날짜를 연속 기간으로 추정하지 않으며, 명시적인 범위 구분자가 없는 두 날짜나 세 날짜 이상은 후보 생성을 거부한다.

## 나라일터 검토

기존 분류기와 증거 검토기를 그대로 재사용했다.

| 이번 보존 표본 | 건수 |
|---|---:|
| 최종합격자 발표·후보자 등록으로 신규 모집 대상 제외 | 1 |
| 상세 분류 불일치로 차단 | 1 |
| 공식 원문·접수 기간 또는 상세 추가 확인 필요 | 4 |
| 신규 지원 가능 자동 인정 | 0 |

이 숫자는 6건 표본의 결과이며 전체 지자체에 진행 채용이 없다는 뜻이 아니다. ID 20의 상세 분류 불일치는 계속 차단한다. API 종료일이 남은 ID 307403도 최종합격자 발표·등록 안내이므로 신규 모집으로 표시하지 않는다.

모바일 검토 화면은 공고별 카드 형태로 제목·API 마감일·처리를 표시한다. 최초 스크린샷에서 제목 열이 과도하게 좁아지는 문제가 확인되어 보완했고, 320·390px에서 읽을 수 있는 제목 너비를 브라우저 검사에 추가했다.

## 실행과 검토 파일

기본 실행은 외부 API를 호출하지 않는다.

```sh
python scripts/build_additional_api_candidate.py
```

매번 새 checkout 또는 아직 후보 출력 폴더가 없는 작업 공간에서 실행한다. 기존 결과를 덮어써 실패한 실행이 과거 성공 결과처럼 보이게 하지 않는다.

`additional-api-candidate-output/`에는 다음 7개 파일이 생성된다.

- `index.html`: 시험일정·나라일터 검토 화면
- `civil-service-exams.html`: 기존 화면을 재사용한 후보 일정 페이지
- `data/civil-service/2026.json`: 화면 형식으로 변환한 전체 28행
- `data/civil-service/years.json`: 검증된 2026년 선택지
- `mpm-source-records.json`: 날짜 표시 변환 전 검증 행
- `gojobs-candidate.json`: 비어 있는 신규 후보 목록과 6건 검토 기록
- `report.json`: 범위·시각·출처·원본 해시와 보존 결과

일정 페이지는 JSON을 fetch하므로 HTTP 서버에서 검토해야 한다. `index.html`의 정적 검토 표와 함께 브라우저 검증 스크린샷도 artifact에 보관했다.

명시적으로 선택한 수동 실행에서는 `--live-exam`으로 `MPM_EXAM_KEY`를 사용해 2026년 MPM API의 새 검토 후보를 만들 수 있다. 워크플로의 `live_exam` 기본값은 false다. 이번 실행에서는 이 단계가 **skipped**였고, 전체 행 수집 경로는 모의 응답으로 검증했다. 이번 결과를 새 실 API 조회 성공이나 최신 변경 공지 전수 확인으로 표현하지 않는다.
