## 보존 정책과 한계

- 개인 기록 키(saved/apps/prefs/spec 및 백업·복구 사본)를 변경·초기화하지 않는다. 탐색은 history + 메모리 + sessionStorage `careerpick-browse-v1`에 분리한다. URL에 메모·토큰·개인 설정을 추가하지 않는다. 진입 URL의 q는 초기 조건으로만 쓰고 첫 검색 수정 시 URL에서 제거하며, 이후 입력은 탐색 세션에 보존한다.
- 같은 탭의 새로고침·상세 재로딩·방문 기록 이동은 복원한다. 새 브라우저/새 기기로의 복원은 제공하지 않는다. 브라우저가 닫힌 탭의 세션을 복원하는지는 해당 브라우저 동작에 따른다.
- 손상·미지원 버전·잘못된 자료형은 무시하거나 유효 필드만 사용한다. sessionStorage 접근 실패는 메모리/history로 계속 동작한다. History API 실패 시 상세를 열고 닫을 수 있게 하며 개인 기록에 쓰지 않는다.
- 카드가 사라지면 기존 스크롤을 유효 범위로 제한하여 복원한다. 카드가 있으면 상대 위치와 링크 초점을 복원한다. 새 검색은 결과 시작점으로 이동한다.
- 외부 이동은 합성 공식 링크의 새 탭 열기/닫기로 검증한다. 실제 공식 사이트 로그인·지원·알림 수신을 검증한 것이 아니다.
- Android Chrome/iPhone Safari 물리 기기, 실제 기기 뒤로가기·화면 회전·백그라운드 복귀·BFCache는 미검증이다. 화면 너비 변경·루트 글자 200%·브라우저 history·pageshow 대응 코드와 실기기 결과를 구분한다.

## 검증 방식의 보완

서비스워커 반복 시험은 같은 격리 프로필과 같은 기록을 유지하며 v1→v2→v3의 서로 다른 실제 워커를 적용한다. 임시 503 서버 장애와 브라우저 오프라인 설정을 함께 사용하고, 실제 보관 응답 표식 및 개인 기록 원본 일치를 확인한다. 시험 중 원본 워커로 되돌리거나 미래 Last-Modified 시각을 주지 않는다. 새 컨트롤러로 바뀐 뒤 버전 메시지를 한 번 보내 확인한다. 이전 워커에 매 프레임 메시지를 보내는 폴링은 제거했다. 캐시/버전 시험의 기존 대기 실패와 실제 기록 손실을 혼동하지 않는다.

초회 방문에서 보관되지 않은 자원은 오프라인 503 안내로 처리한다. 따로 보관된 앱 파일/자료가 있는 오프라인 왕복과, 어떤 앱 자원도 없는 최초 오프라인 방문을 같은 성공으로 보고하지 않는다.
