# 맞춤 공고 자동 발송 복구

운영자가 2026-11-03 미래 맞춤 공고 자동 발송 재개를 승인했다. 전체 구독자에게 같은 공고를 일괄 발송하는 기능이 아니다.

## 확인된 상태와 적용 경계

- OneSignal 단일 기기 시험 e223741c-fa84-4083-b142-800de41e04fe: 19:08:18 KST 발송1·Delivered1·실패0. 운영자가 실제 수신 및 a306597 상세 진입 확인.
- 새 공개 주소의 구독/관심 조건 동기화는 기존 구현을 유지한다.
- 자동 발송 키와 비공개 원장은 아직 연결되지 않았다. 코드 복구·모의 검증은 실제 서버 발송 성공이 아니다.
- 기존 검증된 발송 코드/원장/CAS큐/차단기를 재사용한다. Threads·다른 SNS·기존 수집·Pages 워크플로는 수정하지 않는다.
- 새 수집 예약을 추가하지 않는다. 기존 3시간 수집 자연 실행이 성공한 뒤 workflow_run으로 실행한다. 실패 수집/브랜치/외부 저장소/수동 수집으로 발송하지 않는다.
- 최초 시작 시 현재 공고 ID를 비공개 기준으로 저장하고 기존 공고 소급 발송은 하지 않는다. 이후 새 공고만 대상으로 한다.
- 구독자 전체를 순환 조회하되 회차당 최대100명 검증·발송3건, 남은 대상은 비공개 커서/큐로 유지한다. 이는 전원 즉시 발송을 뜻하지 않는다.
- 관심 조건/동의/구독 상태를 발송 직전에 다시 확인한다. 마감/취소/공식 원문 미확인은 발송하지 않는다. D-1 저장공고 알림은 제외한다.
- 공고 링크는 https://kllollain-max.github.io/careerpick/jobs/ID.html 고정이며 공고 데이터의 외부 URL을 신뢰하지 않는다.
- 예약/accepted/uncertain은 영구 기록한다. 응답 손실·저장 실패·구독 해지·권한 오류 때 재전송하지 않는다.

## 필요한 연결 (Secret 값은 문서/공개 로그에 넣지 않는다)

1. CP_ONESIGNAL_REST_API_KEY: 기존 CareerPick 앱의 API 키.
2. CP_LEDGER_REPOSITORY: 기존 비공개 발송 원장 저장소 owner/name. 기존 원장이 있다면 반드시 그것을 재사용하고 이력을 보존한다.
3. CP_LEDGER_TOKEN: 위 비공개 저장소에만 Contents 읽기/쓰기 가능한 인증키. 사이트 공개 저장소는 원장으로 거절한다.

구독자 목록/관심 조건/구독 ID/서명된 내보내기 URL을 공개 저장소·Actions 로그·산출물에 저장하지 않는다. GitHub 및 OneSignal 자격 증명 생성·등록은 소유자가 직접 수행한다.

## 활성화 순서

1. CP_ENABLE_ALL_OPTED_IN_ROLLOUT 변수 OFF(미설정/0) 상태 유지.
2. 기존 비공개 원장 확보 및 미확정 대조. 빈 원장으로 과거 이력을 대체하지 않는다.
3. 위 Secrets 3개 등록 후 `CareerPick targeted job push` 수동 mode=initialize 실행. 발송0, 기존 파일 덮어쓰기/기존 차단기 자동 해제 없음.
4. mode=check 읽기 전용 실행: 비공개 저장소·원장·기준선·큐·ready 상태 확인.
5. 검증 성공 후 이미 승인된 범위에서 CP_ENABLE_ALL_OPTED_IN_ROLLOUT=1 저장. 다음 자연 수집 성공 후 실행 결과 확인.
6. 실제 대상0이면 정상 무발송. accepted는 서버 접수이며 단말 수신과 구분한다. 미확정은 중단 및 대조, 강제 재실행 금지.
7. 장애 시 변수0으로 단일 발송 경로 중지, 기존 실행 자연 종료 확인, 비공개 상태 보존. 원장 삭제/초기화 금지.

격리 검증: `python tests/run_alert_recovery.py` (네트워크 강제 차단, 기존 대규모 스트레스2건 제외). 기존 일괄 전체 회귀·Threads 검증을 반복하지 않는다.
