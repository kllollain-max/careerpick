# 커리어픽 Threads 마스터 프롬프트 운영

2026년 11월 6일 사용자가 제공한 문서의 마스터 프롬프트를 실제 AI 원고 작성 입력으로 연결한다. 기존 하루 4회 게시기와 원격 중복 방지는 유지하며, 시간별 작업은 미리 원고를 작성·검수하고 실패를 복구한다. 글 생성, 원고 저장, 코드 적용, 실제 게시 성공은 별도로 기록한다.

## 게시 흐름

1. 기존 ChatGPT 예약 `6ae092084b988191a23a38300212ebdc`가 최신 main의 원문 프롬프트와 사실 자료를 읽는다.
2. AI가 각 슬롯의 서로 다른 본문을 작성하고 공식 원문·첨부와 대조한다. 기계 검사는 의미상 사실검수의 대체물이 아니다.
3. 검사를 통과한 `ready` JSON을 `threads-publisher-state`의 `threads/writer-queue.json`에 blob SHA 조건부 쓰기로 보관한다.
4. 기존 `threads_auto.yml`은 현재 정규 슬롯의 원고만 소비한다. 대기열이 없거나 원문이 바뀌면 이전 고정 문장으로 대신 게시하지 않는다.
5. 마지막 실제 성공 이력에서 이미지 교대를 결정하고, 해당 회차 카드가 필요하면 렌더·파일 검사·공개 바이트 해시 검증을 거친다.
6. 원본·기간·CTA·슬롯·중복을 다시 검사한 뒤 원격 슬롯 청구를 확보하고 한 개 본문만 게시한다. 실제 Meta 조회와 영수증을 대조한다.

| 한국시간 | 형식 | 전개 |
|---|---|---|
| 08:00 | reader_story | 독자 조건과 실제 채용조건을 연결하는 문단 |
| 12:00 | key_facts | 확인된 인원·조건을 대응한 항목 요약 |
| 16:00 | job_explainer | 실제 업무와 필수 자격을 설명하는 문단 |
| 20:00 | application_checklist | 지원 준비·제한사항·마감 체크리스트 |

스케줄은 기준 시각이며 GitHub의 예약 실행은 지연될 수 있다. 기존 2시간 지연 허용과 하루 최대 본문 4건을 유지한다. 과거 슬롯 보충·시험 게시·수동 즉시 게시로 횟수를 늘리지 않는다. 시간별 writer/점검 실행은 게시 횟수에 포함되지 않는다.

## 원문과 입력

- `threads/prompts/master-v1.1.txt`: 첨부 DOCX의 B절 완성 프롬프트 원문. 사례분석·타인의 과거 채용조건은 분리했다.
- `threads/writer-policy.json`: 원문 SHA-256, 첨부 원본 SHA-256, CTA, 4슬롯·형식, 450자, 24시간 검수 유효기간.
- `threads/prompts/automation-task.txt`: 기존 시간별 예약에 저장하는 실제 작업 지시문.
- `scripts/threads_writer_input.py`: 실제 최신 목록/상세·운영 확인·과거 공고 ID·최근10개·프롬프트·다음24시간 슬롯을 읽기 전용으로 모은다.

```bash
python scripts/threads_writer_input.py --limit 24 > writer-input.json
python scripts/threads_writer_input.py --check-queue writer-queue.json
```

writer는 공고를 직접 읽고 자연스러운 한국어를 작성한다. 위 스크립트가 문구를 생성하거나 외부 AI API를 호출하는 것은 아니다. 새 비밀키나 유료 모델 서비스를 추가하지 않는다.

## 본문 계약

본문 마지막은 빈 줄 다음 정확히 한 번 아래 문장이다.

> 자세한 채용정보는 프로필 링크를 확인하세요.

새 원고는 해요체·평문·450자 이내이며 URL·해시태그·별도 댓글/저장/공유/팔로우 요구와 작성자 답글이 없다. 필요한 채용조건은 본문에 담고 클릭을 유도하기 위해 숨기지 않는다. 새로운 `master_job`의 답글 없음은 정상이다. 이전 게시물·답글 원문은 수정하지 않는다.

ALIO 게시기간은 실제 원서 접수기간의 대체값이 아니다. 기관 공식 공고·첨부와 상세 지원자격/전형 원문에서 실제 접수기간과 모집단위별 조건을 확인한다. 출처 미확인·조건 충돌·종료시각 미상인 마감 당일·분량 내 필수조건 보존 불가는 draft/hold이며 게시하지 않는다.

`scripts/threads_writer_queue.py`의 검증 경계는 `ready`, 프롬프트 해시, 현 원문 지문, 최근24시간 확인, 현재 수집 미확인ID 제외, 접수기간 근거, 프로필 안내 대상, 4형식·CTA·길이·중복과 이미지 사실을 확인한다. 근거 문구를 보존하지만 사람이 읽는 의미 전체를 자동 증명한다고 주장하지 않는다.

## 대기열 및 증거 필드

최상위는 `{schema_version: 1, entries: [...]}`이며 항목은 다음 필드를 갖는다.

- `scheduled_at`, `format_id`, `notice_id`, `prompt_sha256`.
- `source_post_sha256`, `source_detail_sha256`: canonical JSON SHA-256. ALIO 상세의 최상위 달력 계산값 `decimalDay`만 제외한다.
- `writer`: 원문 JSON 규격의 `status`, `post_text`, `draft_text`, `reply_texts`, `review`.
- `image_job`: `id`, `org`, `title`, `count`, `employment`, `location`, `due`, `deadline_label`.

추가 검수 증거는 `review.application_period`, `review.profile_target`, `review.source_refs`, `review.fact_evidence`다. 정확한 사용 계약은 예약 지시문과 검증기의 사례 테스트를 따른다. 출처의 시각 미기재를 임의 00시·18시·23시59분으로 채우지 않는다. 이미지의 `due`와 `deadline_label`도 검증한 실제 접수마감만 표시한다.

예약할 때 원고 전체를 게시 이력의 `writer_entry`에 복사하고 지문을 고정한다. 이미 시작/예약된 원고를 writer가 교체해도 게시기의 보관본을 바꾸지는 못하며, 게시 직전 보관본 무결성과 최신 공식 원문을 재검사한다. 최초4건 이후의 대기열은 같은 시간별 예약이 실제로 갱신한다.

## 이미지 품질과 교대

교대는 마지막 실제 `published` 기록의 이미지 유무를 따른다. 날짜 변경·준비 실패·재시도는 순서를 초기화하거나 소비하지 않는다. 이미지가 필요한 회차에서 이미지가 준비되지 않으면 텍스트만 게시하지 않는다.

카드는 1080×1080 RGB JPEG, 최대8MB, 높은 JPEG 품질과 4:4:4 설정이다. 긴 기관명·직무·고용형태·지역은 말줄임하지 않고 줄바꿈과 글꼴 크기로 표시하며, 수용 불가면 오류로 처리한다. 정상 디코딩·정확한 치수·문자 지원·잘림 방지와 공개 URL 바이트의 SHA-256 일치를 검사한다. 본문은 이미지 없이도 지원 판단에 필요한 내용을 담는다.

## 자동 복구 경계

- 읽기 요청의 일시 통신·429·5xx: 최대3회, 짧은 backoff와 Retry-After 존중. 긴 제한·401·403은 무한 재시도하지 않는다.
- 원래 runner에서 원격 청구 시도 전 확정 실패: `failed`, `safe_no_send`, 실패단계를 남기며 다음 정규 슬롯을 막는 pending으로 방치하지 않는다.
- 청구 시도 직전 `claim_attempted`를 먼저 기록한다. 이후 응답이 불명확하면 재전송하지 않는다.
- 영수증 저장 응답 유실: 정확히 같은 accepted 내용을 읽어 확인할 수 있으면 저장 완료로 판단한다. 게시 POST를 반복하지 않는다.
- 원격 accepted 영수증과 실제 Meta 본문/ID가 일치: 다음 정규 실행의 읽기 전용 복구로 main 이력을 복원한다. 일부만 복구되어도 확인된 기록은 먼저 저장하고, 미확정 건이 있으면 새 게시를 막는다.
- 원격 sending·게시 여부 불명·권한 문제: 기록 보존 후 시간별 작업이 원인·코드·입력·검증·재개 조건을 처리한다. 실제 권한 변경·소유자 재인증이 필요한 경우만 사용자 조치를 알린다.

관련 실패 경로는 회귀검사를 추가해 재발을 방지한다. 최신 main 및 열린 PR을 대조하고, 이 요청 범위의 Threads 수정만 검증 후 적용한다. 원장 삭제, claim 초기화, POST 무한 재시도, 계정/하루한도 변경, D단계 활성화는 복구 방법으로 쓰지 않는다.

## 검증 기록

로컬 검사: Threads 경계·복구·카드·기존 이관/후보/청구 검사 72개와 복원된 기존 편집/콘텐츠 검사 18개 통과. 긴 한국어 카드의 실제 렌더를 열어 잘림·겹침과 정확한 CTA를 확인했다. 수정 전 게시 이력과 채용 원본은 보존했다. PR의 동일 코드 SHA에 대한 원격 CI와 초기 대기열 검수 결과를 추가 확인한 뒤 적용한다.

코드·대기열 준비는 실제 새 정책 게시 성공과 다르다. 첫 자연 회차의 게시 ID·시각·본문·미디어·형식은 시간별 예약이 별도 확인하고 한 번 보고한다. 외부 장애나 인증 만료까지 포함한 실패0은 보장하지 않는다.
