## 나라일터에서 남은 문제

두 목록과 첫 두 상세는 HTTP·응용 결과코드·XML 구조 및 공고 검증을 통과했다. 첫 두 상세는 선택 순서상 공개경쟁과 경력경쟁에서 각각 한 건이며, 목록과 ID·제목·정규화한 분류가 일치했다.

세 번째 상세는 요청 ID 일치 검사 뒤 `invalid_classification_pair`에서 중단됐다. 안전하게 남긴 진단은 `type01=g01`, `type02=unknown`이다. 해당 목록은 지방공무원 `g02` 필터를 통과했으므로, 이 상세를 정상 지방공무원 공고로 받아들이거나 미지의 분류를 추정하지 않는다. 실패한 공고 ID와 미지의 코드 원문은 현재 로그에 없으며 이를 복원했다고 주장하지 않는다.

이 때문에 **전체 GitHub 실행 결론은 failure**다. 이는 두 키가 모두 잘못됐다는 뜻이 아니다. 현재 공통 검증기의 `authentication_verified`는 `client.verify()` 전체가 정상 반환한 뒤에만 true가 되므로, GOJOBS의 보수적인 false와 실제 성공한 인증 응답을 구분해야 한다. [기계 판독 기록](evidence/additional-api-registration-20261103.json)은 원본 보고서와 이 해석을 함께 보존한다.

인증과 두 종류의 목록·상세 연결은 이미 입증됐으므로 추가 재시도는 하지 않았다. 실제 수집으로 확장할 때는 실패 공고의 식별값과 이미 통과한 결과를 함께 남기고, 분류가 맞지 않는 공고를 분리하는 처리가 필요하다. 현재 검증은 분류 기준을 엄격하게 유지한다.

## 실제 응답 차이에 맞춘 수정

- 나라일터의 기관·채용 구분 필드가 문서와 반대로 오는 경우를 관찰했다. 서로 겹치지 않는 g/e 코드 집합으로 두 배치를 구분하고, 정규화 후 요청한 `g02` 및 `e01`·`e02`와 정확히 일치할 때만 허용한다.
- 선택적인 원문 링크는 핵심 공고 데이터와 별도 검사한다. 유효한 절대 HTTP(S) URL만 반환하고 사용할 수 없는 원문은 제외한다. 상태와 집계만 남기며 주소를 추정하거나 링크에 접속하지 않는다. 최종 검증이 세 번째 상세에서 중단돼 전체 링크 집계는 이번 로그에 남지 않았다.
- 시험일정의 `시험장소공고일`에 한해 관찰된 JSON null을 공란으로 처리한다. 다른 필드 자료형·날짜 유효성·연도·행 수 검증은 유지한다.
