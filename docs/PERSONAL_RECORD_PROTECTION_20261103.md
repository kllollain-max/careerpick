## 범위와 저장 방식

PR #11과 `fix/core-function-audit-20261103` 브랜치에서 기존 핵심 기능 수정을 이어서 보완했다. 병합·공개 배포는 하지 않는다. 시험 데이터와 격리 Chromium 프로필만 사용한다. 실제 개인 기록·구주소 개인 백업은 확보하지 않았으며 개인 백업 파일을 저장소나 CI 아티팩트에 올리지 않는다.

개인 기록은 브라우저 localStorage에 저장한다. 계정 로그인에 따른 기록 동기화나 개인 기록의 자동 클라우드 백업은 제공하지 않는다. Git 저장소/홈페이지 복구 ZIP과 개인 기록 JSON 백업은 별개다.

접두사가 있는 ID는 출처를 보존한다. 접두사 없는 과거 ID는 출처를 확정할 수 없다. 같은 ID에서 내용이 충돌하면 기존 기록을 그대로 두고 가져온 원본 전체를 보관하며, 제목·기관·수정 시각으로 다른 공고를 임의 연결하지 않는다. 실제 구주소 백업 없이 모든 과거 식별자의 동일성을 보증하지 않는다.

## 추가 수정

1. 파일 선택 후 형식/버전/크기 검증 → 항목별 건수·신규·중복·충돌·오류 수와 영향 미리보기 → 확인 후 적용. 미리보기 이후 다른 탭 변경도 다시 검사한다.
2. 파일 다운로드 이름에 KST 날짜·시각을 포함한다. 서비스 식별·생성 시각·건수를 파일에 보관하고, SDK 저장소는 백업 허용목록에서 제외한다. 인증 필드는 구조화된 자료와 복구 원문에서 제외했음을 표시한다. 제외가 있으면 raw_records는 인증 필드를 제거한 사본이며 exact 원문이라고 주장하지 않는다. 기기 안의 변경 전 체크포인트 원문과는 구분한다.
3. 가져오기 전 원문 체크포인트를 검증하고 각 쓰기와 전체 결과를 다시 읽어 검증한다. 마지막 완료 상태 저장까지 확인한 뒤 성공으로 표시한다.
4. 실패하면 정확한 이전 원문으로 되돌리고 재검증한다. 복구까지 실패하거나 창/프로세스가 종료되면 durable hold를 남기고 다음 접속에서 알린다. 미완료 상태를 정상 기록으로 간주하지 않고 추가 변경을 보류한다.
5. 복구 사본 보기·원상복구 기능을 제공한다. 사본 이후 별도의 변경이 있으면 자동 복구를 거부하고 현재 기록과 사본을 모두 보존한다.
6. 같은 백업의 반복 가져오기는 공고·원본 스냅샷을 중복 생성하지 않는다. 충돌 상태·메모·설정은 기존 값을 우선하며 들어온 원본을 화면에서 나중에 확인할 수 있다. HTML을 실행하지 않고 텍스트로 표시한다.
7. 내 스펙도 읽기·쓰기 실패를 감지하고, 성공 확인 전에 메모리 상태를 바꾸거나 창을 닫지 않는다.
8. 백업·가져오기 도구와 보존 범위 안내를 피드가 없어도 사용할 수 있는 독립 영역에 둔다.

## 복구 단계

prepared → 활성 키 적용·재검증 → complete. 실패하면 rolled_back 또는 recovery_required. prepared로 중단된 경우에도 다음 접속에서 복구 보류를 인식한다. 복구는 원문/적용 예정 값 중 하나와 현재 값이 일치하는 경우에만 수행해 이후의 다른 변경을 덮어쓰지 않는다.

브라우저가 원본 사본을 저장할 공간·권한조차 제공하지 않으면 새 변경을 수행하지 않는다. 저장소가 삭제되었거나 사본도 접근할 수 없는 경우에는 이미 다운로드한 백업이 필요하다. 원본을 알 수 없는 손상 내용은 추정해 만들지 않는다.

## 구주소 이전·남은 제약

- 구주소 `https://jobinfo-hub.github.io/`와 새주소는 서로 다른 origin이다. 새주소에서 구주소 localStorage를 직접 읽을 수 없다.
- 동일 기기·브라우저의 구주소에서 JSON을 내보내고 새주소에서 가져온다. 구주소 접근 불가 시 과거 보관한 JSON이 필요하다. 개인 백업을 공개 저장소나 채팅에 올릴 필요는 없다.
- 시험 데이터 과거 v1 형식 호환성은 검사한다. **실제 구주소 개인 기록 이전은 미확인**이다.
- localStorage는 경로가 아닌 origin 단위다. 같은 호스트의 다른 프로젝트가 동일한 saved/apps/prefs/spec 키를 쓰면 충돌할 수 있다. 이번 수정은 기존 키를 바꾸거나 일괄 이전하지 않는다.
- Web Locks 미지원 브라우저의 완전 동시 쓰기를 원자적으로 보증하지 않는다. 지원 Chromium에서의 동시 변경·충돌 검증과 구분한다.
- Android/iPhone 실기기와 OS가 강제 종료하는 모든 상황을 시험하지 않았다. Chromium 프로세스 중단, 복구, controlled service-worker 교체 및 오프라인 검증은 별도 기록한다.
- 파일 크기는 최대 16MB로 제한한다. 손상/접근 불가 항목이 있는 부분 백업과 미완료 가져오기 상태에서 만든 백업은 정상 완전 복원 파일로 자동 적용하지 않는다.
- 실제 사용자 데이터 복원·운영 반영은 이 PR의 시험 통과와 구분한다. 병합·배포는 승인 대기다.
