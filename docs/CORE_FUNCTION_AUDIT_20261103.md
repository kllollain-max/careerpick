## 검증 범위

- Chromium headless의 새 브라우저 컨텍스트. 모바일은 320·360·390·430px 화면 크기 모의시험, PC는 1440px.
- 실제 Chromium을 종료한 뒤 같은 격리 프로필을 다시 열어 저장·지원 메모 보존을 확인하는 시나리오 포함.
- IME는 합성 composition 이벤트 시험이며 Android/iPhone의 실제 키보드 시험과 다르다.
- 공개 사이트는 실제 공개 파일·공고로 기본 흐름과 저장 실패 재현을 확인했다. 수정판의 상세한 실패 상황은 고정된 시험 피드로 검사한다.
- SDK 모형만 구독·해지를 흉내 낸다. 공급자 API, 실제 구독 변경 또는 실제 알림 발송은 하지 않는다.
- 일반 공식 링크 열기를 실제 지원 완료로 처리하는 새 경로를 추가하지 않았다. 제출 완료 변경에는 사용자 확인을 요구한다.
- 기존 채용 JSON 및 개인 기록 키(`saved`, `apps`, `prefs`, `spec`)의 이름을 유지한다. 채용 JSON 원본을 변경하지 않는 빌드 검사도 통과했다.

## 복구 사본 사용

`원본 포함 JSON 백업`에는 읽을 수 있는 기록과 원문 문자열이 함께 들어간다. 손상 원문의 `raw_records`를 정상 자료라고 간주해 자동 덮어쓰지 않는다. 필요하면 해당 문자열의 손상을 검토하고 정상 백업 형식으로 재구성한 뒤 기존 가져오기 검증을 거친다.

최근 변경 전 사본은 `careerpick-record-checkpoints.records.<키>.raw`, 가져오기 전 사본은 `careerpick-before-import.raw_records`에 보관된다. 이는 최근 사본이며 무제한 이력이 아니다. 동일 기기의 브라우저 데이터 삭제나 기기 분실까지 방어하지 못하므로 다운로드한 JSON을 별도로 보관해야 한다.

손상 내용을 알 수 없거나 저장소 접근 자체가 차단된 부분은 자동 복구 완료로 보고하지 않는다. 정상 부분 표시·원본 보존·추가 쓰기 차단까지가 확인된 범위다.

## 남은 작업·제약

1. 병합·공개 배포는 사용자 승인 대기. 현재 공개 사이트에는 이번 기능 수정이 아직 반영되지 않았다.
2. Android Chrome·iPhone Safari 실기기, 실제 키보드 및 글자 확대/OS 접근성 설정은 미검증.
3. 실제 시험 구독의 서버 등록·수신·알림 클릭 후 해당 공고 이동, 백그라운드 알림은 미검증. 배포 후 승인된 한 기기에서 별도 검증 필요.
4. 서비스워커·오래된 캐시·실제 오프라인 재실행 조합은 전체 실기기 검증을 하지 않았다. 이번 시험은 프로필 격리를 위해 서비스워커를 차단했다.
5. Web Locks 미지원 구형 브라우저는 변경 감지 기능은 제공하지만 완전히 같은 순간의 다중 탭 쓰기를 원자적으로 보장하지 않는다. 실 Safari·구형 브라우저에서 추가 검증 필요.
6. 독립 정적 상세 페이지는 설명을 읽는 화면이며, 저장·지원 편집은 메인 사이트의 상세 모달에서 검증했다.
7. 손상된 실제 사용자 기록을 제공받거나 복구한 것은 아니다. 손상 원문의 완전 복원이 가능한지는 자료별 판단이 필요하다.
