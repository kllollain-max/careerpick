## 이번 수정

- `scripts/check_search_public.py`: 공개 XML/HTML만 읽는 대표 표본 및 명시적 1회 전체 검사. XML 네임스페이스·범위·중복, 필수 안내/가이드 누락, 현재 공고의 사이트맵 누락, HTTP·canonical·noindex·본문·메타·만료 구조화 데이터·내부 링크 검사. 호스트 루트 robots만 효력 검사 대상으로 삼는다. 404 부재를 수집 차단으로 판단하지 않는다. 네트워크 실패는 미확인으로 분리하고 외부 리디렉션·외부 블로그를 따라가지 않는다. 종료 0=검사 통과, 1=관찰된 오류, 2=미확인/검토 필요이다. Googlebot을 사칭하거나 광고를 요청하지 않는다.
- `.github/workflows/public-search-check.yml`: 승인된 배포/정기 운영 완료 뒤 main의 공개 결과를 대표 표본으로 검사하는 읽기 전용 작업 준비. 전체 검사는 수동 선택만. 기존 수집/발송 주기와 권한·비밀 설정은 그대로다. 후보가 승인 병합되기 전에는 이 작업이 운영 중인 것으로 보고하지 않는다.
- `index.html`: 상세 진입 전 현재 검색·지역·고용형태·정렬·추가 표시 범위·스크롤을 방문 기록에 보존한다. 상세에서 돌아오면 기존 빈 검색어로 덮어쓰던 문제를 수정한다. 공고 ID·정적 주소·옛 `#job=` 링크와 저장소 키를 유지한다.
- `privacy.html`: 이미 공개된 안내를 ‘공개 전 개정안’이라고 부르던 상태를 정리한다. 현재 안내 적용일과 아직 확정하지 않은 보유·삭제 운영 기준의 시행일을 구분한다. 제안된 5/30/90일을 채택·실행하지 않는다.
- `about.html`: 실제 잡알리오 저작권 정책 링크와 제3자 권리 예외를 연결한다. API 이용과 첨부·사진·로고의 재사용 권한은 구분한다.
- `guides/after-application-checklist.html`: 기존 글을 재사용해 저장/내 지원→공식 접수 확인→JSON 백업→복원 확인 순서를 보강한다. 가상 기록 예시는 가상으로 표시하고 PDF는 복원 파일이 아님을 안내한다. 신규 글 수를 늘리지 않는다.
- `review-only/host-root/index.html`: Naver 실제 발급 태그를 게시 전 후보에 반영. 기존 실제 AdSense 메타와 함께 스크립트 없이 준비한다. 이 폴더는 프로젝트 공개 빌드에서 제외된다.

## 콘텐츠·권리·광고 검토

기존 가이드 6편을 모두 읽어 필수/우대/가점·기준일·정정·접수 확인·STAR의 사실 근거·NCS 개인 계획 예시를 대조했다. NCS 공식 FAQ/공정채용 자료 및 잡알리오 저작권 정책을 확인했다. 이 검토는 AI의 내용 점검이며 운영자의 사람 검수 완료가 아니다. `review-only/content-signoff.md`의 6편 확인표를 재사용한다. 자동 검사 성공을 인간 검수 기록으로 전환하지 않는다.

현재 ALIO 686건의 독립 상세와 기존 보관 주소를 유지한다. ALIO 게시기간을 실제 접수기간으로 바꾸지 않고, 시각·직무 설명·자격의 원문 확인이 필요한 값은 그대로 표시한다. 전체 현행 공고의 실제 직무 본문을 별도로 확인한 상태가 아니며 일반적인 확인표가 공고별 독자 해설을 대신한다고 판단하지 않는다. 대표 원문의 실제 접수/분야별 업무·서류·제한을 사람이 선별하여 확인하는 단계가 남아 있다. 모집인원을 임의 숫자로 바꾸거나 만료 공고를 새 공고로 재작성하지 않는다.

- 정책상 필수: 실질적 가치 있는 본문, 오해 없는 안내, 실제 데이터 처리와 일치하는 개인정보 공개, 무효 트래픽 방지.
- 조건부: 적용 지역·광고 설정에 따른 동의 및 인증 CMP, JobPosting을 사용하는 경우 실제 본문/마감 일치, 제3자 첨부·이미지의 권리 조건.
- 권장 개선: sitemap·canonical·Search Console·Naver 도구, 문의/소개 접근성, ads.txt. 이들을 모두 동일한 AdSense 승인 필수조건으로 부르지 않는다.
- 계정/운영자 확인: 실제 적용 계약·이전 항목/근거, OneSignal 및 비공개 발송 기록의 목적별 보유/삭제 실행 방식, 사람이 검토할 콘텐츠, 본인/지급 정보, 루트 게시 권한.

현재 공개 빌드와 후보 빌드 모두 실제 광고 요청이 없다. 사람 검토된 가이드를 추후 후보로 두며, 저장·내 지원·설정·빈 검색·로딩·오류·미완성 화면에는 초기 광고를 배치하지 않는 안을 유지한다. 같은 URL의 화면 상태를 URL 제외만으로 해결한다고 가정하지 않는다. 광고 활성화에는 별도 상태 제어·동의 구현·계정 확인·명시 승인이 필요하다.

## 운영·소유확인 준비와 되돌리기

호스트 `/`, `/robots.txt`, `/ads.txt`는 현재 404다. 루트 저장소 `kllollain-max/kllollain-max.github.io` 조회 404는 미존재 또는 연결 권한 부족을 구별하지 못한다. 먼저 운영자에게 루트 게시/필요시 새 저장소 생성을 승인받고 기존 관리 주체와 파일을 확인해야 한다. 승인되면 검토한 index·robots·ads.txt 3개만 배포하고 호스트 루트 응답과 실제 태그/게시자 행을 확인한 뒤 Naver 소유확인 및 사이트맵 제출, 승인된 AdSense 소유확인을 진행한다. 도메인 구매·DNS·프로젝트 이전·개인 기록 변경은 이 제안에 포함하지 않는다.

프로젝트 변경은 새 PR만 승인 병합·배포하며 실패 시 그 PR을 되돌리고 마지막 확인된 배포 SHA의 산출물로 복구한다. 이후 생긴 수집 자료·원장·개인 기록을 초기화하거나 전체 main을 과거로 강제 재설정하지 않는다. 루트 게시 승인을 받기 전에는 소유확인·ads.txt를 완료로 표시하지 않는다.
