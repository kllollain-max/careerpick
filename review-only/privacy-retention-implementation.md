# 보유·삭제 기준 적용 준비 — 검토용 구현

작성일: 2026-11-04(KST). 사용자 계속 진행 요청에 따라 기준안의 적용 준비를 구현했다. 공개 시행일·운영 삭제 활성화·기존 자료 파기를 확정한 문서는 아니다.

## 구현한 범위

- `scripts/privacy_retention.py`: 개인정보 본문이 아닌 최소 메타데이터로 보유 상한·목적 종료·해지 시각을 판정한다. 네트워크·계정·키·파일 수정·삭제·발송 코드는 없다. CLI에는 적용 모드가 없고 기본 출력은 집계 결과뿐이다.
- `tests/test_privacy_retention.py`: 26개 검사로 30/90일 경계, 목적 조기 종료, 문의 후속 처리, 5일을 기다리지 않는 해지 처리, 본인·범위·백업·복구·중복 방지 조건 누락, 구형 원장, 날짜·입력 오류 및 식별정보 비노출을 검증한다.
- 기존 애드센스 검토 CI에 해당 검사와 가상 메타데이터 예제를 추가했다. 실제 운영 워크플로·수집·웹푸시 설정·비공개 데이터는 수정하지 않았다.

## 판정 결과 읽는 법

| 결과 | 의미 |
|---|---|
| `client_managed` | 이용자 기기 기록. 운영자 자동 삭제 대상으로 처리하지 않음 |
| `keep` | 현재 확인한 목적·상한 안에 있음. 미래 보관 권한을 무제한 부여하지 않음 |
| `review_closure` | 미응답 문의 30일 경과 등 종결 검토가 필요함. 자동 삭제 아님 |
| `restricted_hold` | 별도로 확인한 유효한 법적 보존 근거·기간이 있는 건의 분리 보관 검토 |
| `blocked` | 시각·신원·범위·사본·복구·재발송 방지 등 확인이 부족함. 수동 검토 필요 |
| `delete_candidate` | 검토할 삭제 후보. 실제 삭제 권한이나 외부 삭제 완료를 뜻하지 않음 |

판정 입력의 확인 플래그는 호출자가 제공하는 증거 상태의 표현이다. 이 계산기가 외부 제공자의 삭제 결과·계약·신원·백업 처리를 자체 검증하지 않는다. `live_activation_ready`는 항상 false, 실제 삭제·발송 건수는 항상 0이다.

## 적용 계산의 주요 조건

- 일반 문의는 목적이 끝나면 바로 삭제 후보로 본다. 실제 후속 처리가 필요한 건만 완료 후 최대 30일을 쓰고 후속 목적이 먼저 끝나면 앞당긴다.
- 해지·삭제 사유와 요청 대상 통제가 확인되면 즉시 발송 제외 후보·삭제 검토 후보로 분류한다. 5일은 내부 완료 목표이며 대기 기간이 아니다.
- 상세 로그는 발생 후 30일, 중복 방지 최소 기록은 정상 처리 후 90일을 상한으로 계산한다. 원래 사건 시각의 검증이 필요하며 재조회·재시도로 기준 시각을 새로 찍지 않는다.
- 원래 시각이 없는 기존 기록, 예약·발송 결과 미확정 기록, 확인되지 않은 법적 보존 주장 등은 자동 삭제 후보로 넘기지 않는다. 자료를 영구 보관하라는 뜻이 아니라 기한 내 사실 확인·수동 처리가 필요하다는 결과다.
- 사본 범위·복구 방지 확인이 없으면 후보 승격을 막는다. 중복 방지 기록은 별도의 과거 공고 재발송 방지 검증도 필요하다.
- 백업은 원본의 만료 시각을 따른다. 새 사본 생성·복원으로 보관기간을 연장하지 않는다.

## 현재 저장 구조와의 연결 상태

현재 운영 대기열·원장과 분리된 검토 모듈이다. 기존 v1 형식에는 확정된 보유기간 메타데이터가 없으므로 단순히 날짜를 추가하거나 일괄 비우지 않는다. OneSignal과 Git 이력·복제본의 실제 삭제도 별도 준비가 필요하다.

운영 연결에 필요한 다음 작업은 (1) 신규 기록의 실제 발생·확정 시각을 보관할 저장 스키마, (2) 최소한의 본인·범위 검증, (3) Git 과거 이력이 개인정보를 되살리지 않도록 하는 저장·사본 처리, (4) TTL 후 재발송과 복구 시 정보 재등장을 막는 검증, (5) 제공자별 처리·국외 이전 정보 확인이다. 이 항목이 완료되기 전에는 개인정보처리방침에 자동 삭제가 작동 중이라고 표시하지 않는다.

후속 읽기 전용 점검에서 OneSignal Free·Web Active·Auto resubscribe 켜짐을 확인했다. 사이트 데이터 삭제 후 재등록 가능성을 개인정보 안내 개정안에 추가했다. 계정 계약·실제 사본 처리와 운영 설정 변경은 대기 중이며, 구체적인 변경안과 외부 처리 확인 범위는 `privacy-provider-readiness.md`에 기록했다.

## 재현

```sh
python -m unittest discover -s tests -p test_privacy_retention.py
python scripts/privacy_retention.py --example --at 2026-11-04T00:00:00+00:00
```

CLI stdin은 `records`와 `evidence`만 포함하는 메타데이터 객체를 받는다. 실제 개인정보·이메일·토큰·구독 ID·본문을 넣지 않는다. 필요 이상의 필드, 시각 불명·미래 사건·역전된 사건 시각·잘못된 확인 플래그는 차단한다. stdout과 오류에는 개별 기록이나 입력값을 출력하지 않는다.

## 공개 산출물 안정성 보완

분리된 빌드·검사 과정에서 일부 기관 페이지 경로 보정이 누락된 재현을 추가 확인했다. `scripts/build_public_site.py`의 변환 파일 쓰기를 임시 파일의 완전한 기록·동기화 후 원자적 교체로 바꾸었다. 출력 내용 보존·교체 실패 시 원본 유지 검사를 포함하고, 빌드 이후 별도 프로세스의 전체 공개 산출물 검사를 수행한다. 이 변경으로 개인정보 삭제 기능이 활성화되는 것은 아니다.
