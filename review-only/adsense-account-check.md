# AdSense 계정·등록 호스트 확인

2026-11-04. 계정 이메일·게시자 ID·인증/지급정보는 이 기록에 넣지 않는다. 루트 배포 후보에만 실제 계정이 제공한 공개 확인용 메타 태그와 ads.txt 행을 준비했다. 비밀키가 아니다.

사용자는 확인된 기존 계정으로 재활성화 절차를 시작하도록 승인했다. ‘계정 다시 활성화’를 누른 뒤 비활성 안내가 사라지고 설정·사이트 메뉴가 열렸다. 새 계정 생성이나 본인·지급정보 입력은 하지 않았다. 화면에는 사이트 연결 등 초기 설정이 남아 있어 계정의 모든 자격·지급·심사 절차가 완료됐다고 보고하지 않는다.

처음 사이트 선택에는 기존 다른 사이트가 있었으며 그 사이트의 광고 설정 상태를 커리어픽 상태로 사용하지 않았다. 해당 사이트를 삭제·변경하지 않았다.

원래 지시의 계정 입력 결과 확인을 위해 `https://kllollain-max.github.io`만 입력·저장했다. `/careerpick/`는 독립 사이트 단위로 등록하지 않았다. 저장 후 계정을 새로 불러오고 사이트 목록에서 호스트가 유지됨을 확인했다. 화면의 마지막 갱신은 2026-11-04 17:21 KST이며 상태는 아래와 같다.

| 단계 | 실제 관찰 |
|---|---|
| 등록 호스트 수락 | 사이트 목록에 kllollain-max.github.io 표시 |
| 사이트 승인 상태 | 검토 필요 |
| ads.txt 상태 | 찾을 수 없음 |
| 소유권 확인 | 미완료. 코드·ads.txt·메타 태그 선택지를 읽었으며 게시 완료 체크·확인 버튼 미실행 |
| 검토 요청 | 비활성·미실행 |
| 실제 광고 | 스크립트 설치·탐색/자동 광고 활성화 미실행 |

홈 화면의 연결 버튼이 저장 직후에는 반응하지 않아 새로고침했고, 이후 나타난 ‘사이트’ 메뉴의 상세 화면에서 확인 방법을 읽었다. 이를 접근 차단이나 Google 거절로 판단하지 않았다.

실제 제공 값으로 `host-root/index.html`의 소유권 메타 태그와 `host-root/ads.txt`를 준비했다. 현재 호스트 루트 404와 관리 저장소 조회 404를 확인했지만 루트 배포는 승인하지 않았으므로 수행하지 않았다. 같은 호스트의 두 프로젝트에 미칠 영향을 확인한 뒤 공개 파일 배포·소유권 확인 범위를 별도로 승인받는다. 심사 요청·광고 활성화는 그다음 단계다.

17:28 KST HTTP 재확인에서 루트 `/`와 `/robots.txt`는 404였다. `/ads.txt`는 이번 요청의 URLError로 HTTP 상태 미확인이다. 앞선 HTTP 404 및 계정의 ‘찾을 수 없음’ 표시와 구분하며, 조회 오류를 서비스 장애나 크롤러 차단으로 단정하지 않는다.

- [Google 사이트 추가와 검토 요청의 구분](https://support.google.com/adsense/answer/12169212?hl=ko)
- [등록 가능한 사이트 형식](https://support.google.com/adsense/answer/12170421?hl=ko)

공식 절차에서 ‘저장’은 사이트 목록에 ‘검토 필요’로 추가하는 단계이며 ‘검토 요청’은 별도다. 이 계정의 실제 사이트 목록과 확인 화면을 근거로 상태를 기록했고, 내부 준비를 ‘준비됨’으로 바꾸지 않았다.
